## 1. Contexto e Motivação

1. **Página Inicial pós-login por Perfil (`usuarios-perfis`)**:
   - Atualmente, ao efetuar login no sistema, todos os usuários são redirecionados indiscriminadamente para o mesmo destino padrão (`/dashboard/`).
   - Perfis de clientes ou usuários com funções específicas necessitam ser direcionados imediatamente para rotas especializadas (ex: `/minha-hospedagem/`, `/user-subscription/`, `/loja/`, etc.).
   - O módulo administrativo `usuarios-perfis` deve permitir configurar formalmente a página inicial de destino pós-login por perfil.

2. **Mapeamento de Múltiplos Layouts por Perfil em `paginas`**:
   - No modelo atual do Conn2Flow, cada registro da tabela `paginas` possui uma única coluna referencial `layout`.
   - Com o advento de portais de autoatendimento com layout próprio (como o `layout-portal-cliente` do `conn2flow-site`), surge uma quebra de consistência: páginas compartilhadas entre perfis (como `/perfil-usuario/`) precisam ser renderizadas com o layout do portal do cliente para consumidores finais, mas devem preservar o layout administrativo padrão para a equipe interna.
   - É necessário estender o modelo de dados de `paginas`, os CRUDs administrativos (`publisher-pages` e `admin-paginas`), o roteador central (`gestor_roteador`) e os controladores de sincronização de recursos para permitir mapear layouts específicos por perfil de usuário.

## 2. Escopo Detalhado por Item

### 🔹 Item 1 — Módulo `usuarios-perfis`: Abas e Seleção de Página Inicial pós-login
- **Arquivos**: `gestor/modulos/usuarios-perfis/` (PHP, JS, JSON e templates).
- **Interface e Comportamento**:
  1. No formulário de inclusão/edição de perfis (`usuarios-perfis`), transformar a estrutura do formulário em abas:
     - **Aba "Módulos"**: Contém a listagem atual de permissões de módulos e operações.
     - **Aba "Acesso"**: Nova aba para configurações gerais de acesso daquele perfil.
  2. Dentro da aba **"Acesso"**:
     - Incluir campo de seleção com autocomplete pesquisando todas as páginas ativas da tabela `paginas` (`id`, `nome`, `caminho`).
     - Rótulo: *"Página Inicial pós-login"* (placeholder: *"Padrão do sistema (/dashboard)"*).
     - Valor salvo: identificador ou caminho da página escolhida.
  3. **Persistência**:
     - Adicionar coluna `pagina_inicial` (VARCHAR(255) NULL) na tabela `usuarios_perfis` via migração Phinx.
  4. **Lógica de Redirecionamento no Login**:
     - No fluxo de autenticação pós-login (`autenticacao.php` ou rotina de finalização de login):
     - Obter o perfil do usuário autenticado. Se o campo `pagina_inicial` estiver preenchido com uma rota válida, redirecionar o usuário para ela. Caso contrário, aplicar o fallback padrão do sistema (`/dashboard`).

## 3. Critérios de Aceite

1. **Página Inicial em `usuarios-perfis`**: O formulário exibe as abas "Módulos" e "Acesso"; o autocomplete de página inicial grava e recupera a rota; o login com usuário desse perfil redireciona diretamente para a rota configurada.
2. **Migrações Limpas**: As migrações de `usuarios_perfis` (`pagina_inicial`) e `paginas` (`layouts_users_profiles`) executam com sucesso no MariaDB sem afetar registros legados.
3. **Toggle de Mapeamento**: `admin-paginas` e `publisher-pages` permitem alternar entre layout padrão e pares dinâmicos de layout ➔ perfil, com adição e remoção fluida de itens.
4. **Roteamento Dinâmico**: `gestor_roteador()` aplica o layout mapeado correspondente ao perfil do usuário autenticado e mantém o layout padrão para usuários não mapeados ou anônimos.
5. **Pipeline de Recursos Íntegro**: `c2f resources:sync` e os controladores de atualização exportam e importam `layouts_users_profiles` sem perda de dados.
6. **Suíte de Testes**: Testes automatizados cobrindo o roteador e o novo campo verdes.
