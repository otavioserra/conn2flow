# Requisição 132 — Limpeza do HTML entregue ao navegador nas páginas públicas

## Origem

Levantada pelo operador em 2026-08-25, ao inspecionar o código-fonte de uma página pública do
projeto Photon (`temp/problema.html`, 138,7 KB):

> "essa página que eu te dei do problema, você viu que está tudo... é a página pública. A gente
> precisava fazer um jeito de tirar todos os comentários. Porque está parecendo um monte de
> comentário de sistema, e não é legal mostrar isso numa página pública."

## Problema

O HTML servido carrega tudo o que foi escrito para quem desenvolve:

| | medido na página real |
| --- | --- |
| comentários HTML | 5,9 KB em **95 blocos** |
| comentários CSS | 11,5 KB em **45 blocos** |
| indentação | 33,1 KB |
| **total descartável** | **50,5 KB — 36% do arquivo** |

Não é só peso. Vários desses comentários descrevem a arquitetura interna para qualquer visitante
que abra o código-fonte — decisões de layout, nomes de lote, o que cada bloco resolve e por quê.

## O que se pede

1. Remover comentários de HTML, comentários de CSS e a indentação do HTML entregue.
2. **Configurável**, e configurável pela tela do Gestor — não só por arquivo.
3. Um modo que permita **ver o resultado da limpeza no ambiente local**, para conferir antes de
   publicar, sem perder a legibilidade do HTML durante o desenvolvimento normal.

## Decisões tomadas com o operador

| pergunta | resposta |
| --- | --- |
| onde a configuração vive | no `.env`, como o `DEVELOPMENT_ENV` — e exposta na tela pelo módulo `admin-environment`, que já edita o `.env` |
| padrão por ambiente | produção limpa, ambiente local legível |
| escopo da limpeza | comentários **e** indentação |

O módulo `admin-environment` foi apontado pelo próprio operador e resolve a aparente contradição
entre "no `.env`" e "via gestor": ele é a tela que edita o `.env`.

## Restrição de ambiente

A chave precisa entrar no template `gestor/autenticacoes.exemplo/dominio/.env`, de onde
`atualizacoes-sistema.php` faz **merge aditivo** para as instalações existentes. O agente está
impedido por regra de permissão de ler ou escrever arquivos `.env*`; a linha foi entregue ao
operador para aplicação manual.

## Segunda rodada (mesma data)

Na homologacao o operador apontou que os comentarios de **JavaScript embutido** continuavam na
pagina, e pediu que o JS tambem fosse limpo e comprimido. A 1a rodada preservava `<script>` inteiro
por considerar o risco alto demais; a solucao foi trocar a ferramenta, nao aceitar o vazamento:
um **scanner com estado** no lugar de expressao regular. Ver BATCH-134, secao "2a rodada".
