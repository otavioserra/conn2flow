# req-215 — Módulos distribuídos: rotina local pedida pelo Central

- **Status:** `in-progress`
- **Modo de Autonomia:** `autonomo_monitorado`
- **Lote Alvo:** `BATCH-223`
- **Data de Criação:** 2026-10-02
- **Origem:** parte do core da REQ-096 do `conn2flow-site` (execução no cliente dos módulos restantes), pedida pelo Engenheiro Chefe Humano no chat.

## Contexto

Na arquitetura dos módulos distribuídos (req-211, req-213, req-214), o painel roda no Central e a execução, no site do cliente. O canal assinado já leva consultas às tabelas de negócio do cliente e avisa o cliente depois de cada escrita (`db.escrita`).

Falta o caso em que o painel precisa de um efeito que só existe no site do cliente: enviar um e-mail com a identidade do site, criar a página pública de um produto, estornar um pagamento com a credencial local, listar os perfis de usuário do site. Hoje esse código roda no Central e age sobre o banco e a configuração do Central.

## Escopo

1. Ação nova no canal assinado: **rotina**. O Central pede a execução de uma rotina nomeada, com argumentos; o cliente executa uma função que o módulo de execução declarou e devolve o retorno.
2. No cliente, só roda rotina declarada no manifesto do módulo de execução (lista fechada). Nome fora da lista é recusado.
3. No Central, uma função para o módulo pedir a rotina quando está em contexto distribuído.
4. O que mais a REQ-096 do site precisar do core para a execução dos módulos no cliente, sem levar regra de negócio do site para o core.

## Fora do escopo

- Abrir tabelas de renderização do core (`paginas`, `layouts`, `componentes`) no canal.
- Regras de e-commerce, assinaturas ou associados: ficam no `conn2flow-site`.

## Critérios de aceite

- CA-1: rotina declarada roda no cliente e o retorno chega ao Central; rotina não declarada, módulo sem execução, assinatura inválida ou repetição do mesmo pedido são recusados.
- CA-2: fora de contexto distribuído nada muda para os módulos.
- CA-3: testes de unidade cobrindo o protocolo; suíte do core sem regressão.
