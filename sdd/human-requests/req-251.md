## 2. Escopo

Hoje o arranjo de widgets vive em três lugares: o layout próprio do usuário, os layouts salvos dele e o layout publicado por perfil. Falta a lousa como coisa do sistema, com nome, que mais de uma pessoa abre e que a fase 3 vai publicar como página.

1. **Lousa nomeada**: registro do sistema com identificador, nome, modo (grade ou lousa) e os itens (widgets e objetos). Quem administra widgets cria uma lousa a partir do que está na tela, abre uma lousa no próprio layout e grava por cima.
2. **Duplicar**: cópia inteira com outro nome, para testar uma variação.
3. **Versões**: cada gravação por cima guarda a anterior. Dá para listar as versões e restaurar uma; restaurar também guarda a atual.
4. **Excluir**: a lousa sai da lista sem apagar o histórico.

Os layouts salvos (pessoais) e o layout por perfil continuam como estão.

## 3. Critérios de aceite

- [ ] Criar lousa com nome a partir do layout atual; ela aparece para outro administrador.
- [ ] Abrir uma lousa traz modo, widgets, objetos e posições para o próprio layout.
- [ ] Gravar por cima cria versão; restaurar uma versão devolve o conteúdo dela e guarda a que estava.
- [ ] Duplicar gera lousa independente.
- [ ] Excluir tira da lista.
- [ ] Só quem tem `widgets-administrar` lista, cria, altera ou exclui; o servidor recusa os demais.
- [ ] Conteúdo normalizado no servidor, como no layout por perfil.
- [ ] PHPUnit e Vitest verdes; roteiro de navegador em `v3.1-conn2flow.local`; textos nos dois idiomas.
