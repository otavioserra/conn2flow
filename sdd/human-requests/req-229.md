## 1. Contexto e Objetivos

Hoje no Conn2Flow, a esmagadora maioria dos módulos acessa e modifica o estado global do sistema através de `global $_GESTOR;` e escrita livre direta no array (ex.: `$_GESTOR['modulo-id']`, `$_GESTOR['usuario-id']`, etc.). 

Embora isso seja simples e direto, a manipulação global irrestrita:
1. Impede rastreamento de quem alterou o quê no ciclo de vida da requisição;
2. Dificulta testes unitários isolados;
3. Cria alto acoplamento para a futura migração de classes da **Linha 3.1**.

### A Solução Estratégica: O Meio-Termo Controlado
Criar uma **camada de controle e acesso unificado (State/Context Accessor)** com funções determinísticas que encapsulam `$_GESTOR`, adicionando:
- Validação de chaves e tipos;
- Imutabilidade onde necessário (ex.: IDs de sistema e configurações de ambiente);
- Log de auditoria/depuração quando uma chave crítica for sobrescrita;
- Total retrocompatibilidade: o array `$_GESTOR` continua existindo por debaixo dos panos, mas os módulos passam a adotar as funções controladas.

---

## 2. Escopo Detalhado

### 2.1. Funções Core da Biblioteca de Variáveis
Implementar em `gestor/bibliotecas/gestor.php` (ou helper dedicado):
```php
/**
 * Recupera um valor de configuração/estado do sistema com suporte a fallback e notação pontuada.
 * Exemplo: gestor_get('usuario-id') ou gestor_get('banco.conexao.host', 'localhost')
 */
function gestor_get(string $chave, mixed $padrao = null): mixed;

/**
 * Define ou atualiza um valor no estado global de forma segura e controlada.
 * Se a chave for protegida/read-only, emite alerta no log e bloqueia mutação acidental.
 */
function gestor_set(string $chave, mixed $valor): bool;

/**
 * Verifica a existência de uma chave no estado global.
 */
function gestor_has(string $chave): bool;

/**
 * Retorna uma fatia de contexto delimitada (ex.: dados do módulo ativo ou usuário ativo).
 */
function gestor_contexto(string $escopo): array;
```

### 2.2. Proteção de Chaves Críticas
- Criar allowlist de chaves somente-leitura após inicialização do kernel:
  - `raiz-absoluta`, `url-raiz`, `linguagem-codigo`, `versao-num`.
- Se um módulo tentar sobrescrever essas chaves via `gestor_set()`, registrar erro no log de sistema e manter a integridade do Core.

### 2.3. Preparação Arquitetural para a Versão 3.1
- Implementar as funções já utilizando internamente uma classe estática enxuta ou Singleton (`GestorState::get()`, `GestorState::set()`), enquanto as funções procedurais `gestor_get()` e `gestor_set()` atuam como fachada pública estável.
- Dessa forma, quando iniciarmos a migração de classes na **Linha 3.1**, os módulos já estarão desacoplados do `global $_GESTOR` e prontos para injeção de dependência.
