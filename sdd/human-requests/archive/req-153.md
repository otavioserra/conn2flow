# req-153: Falha no teste automatizado AdminCronReq032Test durante o release no CI

- **Status do intake**: ready-for-intake
- **Data**: 2026-09-02
- **Origem**: Falha no job PHPUnit (Backend Tests) do GitHub Actions na tag de release `gestor-v2.10.2` (Run `33628994912`)
- **Classificação**: Correção de teste / Metadados de recurso
- **Batch**: BATCH-155

---

## 1. O Sintoma

Ao executar a suíte de testes PHPUnit no CI (`vendor/bin/phpunit`), ocorre a seguinte falha:

```text
1) AdminCronReq032Test::testChecksumsNascemVaziosParaOPipelineCalcular
[pt-br] checksum html não pode ser escrito à mão
Failed asserting that two strings are identical.
--- Expected
+++ Actual
@@ @@
-''
+'387ee81b1f9dd115a8d96c7ca2b92d72'

/home/runner/work/conn2flow/conn2flow/tests/Unit/PHP/AdminCronReq032Test.php:369
```

## 2. A Causa Raiz

No metadado do recurso `admin-cron` em `gestor/recursos/admin-cron/admin-cron.pt-br.json`, o campo `checksum.html` foi preenchido manualmente com `'387ee81b1f9dd115a8d96c7ca2b92d72'`. 

Pela especificação do contrato de integridade de recursos (REQ-032 / BATCH-026), os campos de checksum nos arquivos JSON de recursos devem nascer como strings vazias (`""`) para que o pipeline `./c2f manager:update-all` / `c2f resources:sync` os calcule deterministicamente durante o build/deploy.

## 3. A Solução

1. Editar `gestor/recursos/admin-cron/admin-cron.pt-br.json` e (se aplicável) `admin-cron.en.json`, zerando os campos de `checksum` (`"html": ""`, `"css": ""`, `"js": ""`, etc.).
2. Executar `./c2f manager:update-all` ou `c2f resources:sync` para garantir que a sincronização do ambiente de desenvolvimento permaneça consistente.
3. Executar a suíte de testes `composer test` localmente para confirmar que 100% dos testes PHPUnit passam.

---

## 4. Critérios de Aceite para o Agente Executor

- [ ] O teste `AdminCronReq032Test::testChecksumsNascemVaziosParaOPipelineCalcular` em `tests/Unit/PHP/AdminCronReq032Test.php` passa sem erros.
- [ ] A suíte completa `composer test` roda com 0 falhas.
