## 1. Pedido, nas palavras do Engenheiro Chefe

> "Eu acho importante ter o editor HTML, porque se você pegar todos os outros, inclusive o admin páginas, o publisher index, o publisher pages, eles têm o editor HTML. Porque o editor HTML te dá vários recursos para você alterar ali in loco… é um dos mais importantes. É necessário colocar sim."

> "A clonagem é relativamente simples… é a função de editar sem colocar o campo nome, e depois na hora de salvar é usar o adicionar… faz sim a clonagem."

## 2. Escopo

1. **Editor HTML** nas telas de adicionar, editar e clonar do `dashboard-pages`, no mesmo padrão do `publisher-index`: escolher um modelo carrega o HTML e o CSS dele no editor; o que vale para a página é o conteúdo do editor.
2. O HTML do editor é guardado como o modelo daquela página (com o lugar da lousa e o lugar do título); a página publicada sai dele mais os controles de exibição, como o `publisher-pages` faz com o modelo e os valores.
3. **Clonar**: tela de clonar aberta da listagem e da edição, com os dados da página de origem, nome e endereço em branco; salvar cria outra página.

## 3. Critérios de aceite

- [x] Editor HTML presente em adicionar, editar e clonar.
- [x] Trocar o modelo carrega HTML e CSS dele no editor.
- [x] O que foi escrito no editor aparece na página publicada e volta ao editor na edição seguinte.
- [x] Os controles de exibição continuam valendo sobre o HTML do editor.
- [x] Clonar cria uma página nova, com outro endereço, sem alterar a de origem.
- [x] PHPUnit e Vitest verdes; roteiro de navegador em `v3.1-conn2flow.local`; textos nos dois idiomas.
