## 1. Problema observado

No Lab HestiaCP, `c2f project:update-all snapphoton-lab` sincronizava o core, mas o estágio de banco falhava antes de executar PHP. O projeto tinha um `target` bare-metal válido em `/home/snapphoton/.../conn2flow-gestor`, porém não tinha `dockerPath` — configuração correta para um tenant HestiaCP.

O script `updates-manager-database.sh` aceitava `--project`, mas só aceitava o caminho quando ele era derivável para `/var/www/sites/` e terminava incondicionalmente em `docker exec conn2flow-app`.

Ao liberar a execução host, a validação real revelou ainda que o PHP precisava executar a partir da raiz do Gestor e que o `phinx.php`, incluído dentro de `migracoes()`, não compartilhava o `$_GESTOR` global já usado pelas bibliotecas CLI.

## 2. Escopo aprovado

- Preservar o modo Docker quando `dockerPath` existe ou é derivável do mirror local.
- Selecionar modo host somente quando `target/path_tests` contém o atualizador PHP esperado.
- Executar PHP host a partir da raiz do Gestor, em subshell.
- Manter `--project`, `--tables` e `--force-all` como argumentos separados e validados.
- Remover o `bash -c` intermediário do caminho Docker.
- Compartilhar `$_GESTOR` no bootstrap de produção do `phinx.php`.
- Falhar explicitamente quando nenhum ambiente executável puder ser determinado.

## 3. Critérios de aceite

- [x] Projeto Docker continua resolvendo para `docker exec conn2flow-app php ...`.
- [x] Projeto bare-metal com atualizador válido seleciona `Execution Mode: host`.
- [x] Projeto bare-metal inválido falha sem tentar Docker ou PHP arbitrariamente.
- [x] `project:update-all snapphoton-lab` conclui as cinco etapas no Lab HestiaCP.
- [x] Segunda execução é idempotente no banco (`+0 ~0 =19`).
- [x] Testes focados e suíte PHPUnit completa passam.
- [x] Nenhum segredo ou configuração específica do Lab é incorporado ao core.
