# Requisição 211 — Infraestrutura comum para módulos distribuídos (parte do core da REQ-092 do site)

**Origem**: REQ-092 do `conn2flow-site` (`sdd/human-requests/modulos-distribuidos/`), aprovada pelo Engenheiro Chefe Humano em 2026-10-02. Este arquivo registra no core a parte que mora aqui.
**Lote Vinculado**: `BATCH-219` (`conn2flow` core); no site, `BATCH-086`.
**Status**: `in-review`.
**Modo**: `autonomo_monitorado`.

---

## 1. Pedido

1. Login do módulo distribuído pelo formulário e pela esteira oficiais do `perfil-usuario`, com gancho de ciclo de vida, no lugar do formulário próprio.
2. Ponte transparente: o módulo original roda no Central e as consultas das tabelas de negócio vão, assinadas, para o banco da instalação distribuída.
3. Auditoria do canal: HMAC com comparação de tempo constante, bloqueio de SQL empilhado e de tabelas fora da lista, validade e rotação dos tokens, falha fechada quando o Central não responde.

## 2. Critérios de aceite

1. Acesso sem token a um módulo distribuído leva ao `/signin/` do Central; depois do login completo (inclusive segundo fator) o navegador volta com um código de uso único, trocado entre servidores.
2. Nenhum token em URL nem em armazenamento do navegador.
3. O canal de banco só aceita consultas cujas tabelas estão todas na lista da instalação. Qualquer forma de referência a tabela que não seja um nome simples ou um `SELECT` derivado é recusada.
4. Requisição repetida, vencida ou com assinatura inválida é recusada.
5. Instalação sem contexto distribuído não muda de comportamento.
