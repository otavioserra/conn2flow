## 1. Contexto & Motivação

Atualmente, o ecossistema Conn2Flow adota o princípio de que `resources/` é a Fonte Única da Verdade para autoria, enquanto `gestor/db/data/` serve como artefato compilado determinístico consumido pelo instalador e pelo pipeline de migrações (`db:update`).

A maioria das tabelas principais (`PaginasData.json`, `ComponentesData.json`, `LayoutsData.json`, `VariaveisData.json`, `PromptsIaData.json`, etc.) já é compilada automaticamente. No entanto, **8 tabelas centrais** ainda permanecem como arquivos JSON estáticos mantidos manualmente em `gestor/db/data/`:
1. `ModulosData.json` (`modulos`)
2. `ModulosGruposData.json` (`modulos_grupos`)
3. `ModulosOperacoesData.json` (`modulos_operacoes`)
4. `UsuariosData.json` (`usuarios`)
5. `UsuariosPerfisData.json` (`usuarios_perfis`)
6. `UsuariosPerfisModulosData.json` (`usuarios_perfis_modulos`)
7. `UsuariosPerfisModulosOperacoesData.json` (`usuarios_perfis_modulos_operacoes`)
8. `CategoriasData.json` (`categorias`)

Além disso, os comandos de compilação de recursos (`./c2f resources:sync`, `project:update-all`, `manager:update-all`) forçam uma reconstrução monolítica e acionam o pipeline de Tailwind CSS para todo o sistema, tornando a iteração pesada e provocando timeouts em agentes durante alterações pontuais de dados.

## 2. Objetivos Arquiteturais

### Frente A: Autoria 100% em `resources/` & Compilação Determinística
1. **Sementes Autorais Multi-Idioma**:
   - Criar os arquivos de semente em `gestor/resources/pt-br/` e `gestor/resources/en/`:
     - `modules.json`
     - `module_groups.json`
     - `module_operations.json`
     - `users.json`
     - `user_profiles.json`
     - `user_profiles_modules.json`
     - `user_profiles_modules_operations.json`
     - `categories.json`
   - Atualizar `gestor/resources/resources.map.php` para registrar os novos arquivos no mapa de idiomas.
2. **Contrato Declarativo em `tables_config.json`**:
   - Declarar todas as 8 tabelas em `gestor/resources/tables_config.json` usando `sync_resources: true`, `strategy: "natural_key"` e `metadata_file`.
   - **Blindagem de Produção**: Configurar `insert_only: true` e `preserve_on_user_modified` para `usuarios` (preservando credenciais, hashes de senha e dados de produção).
   - Configurar `natural_key_columns` canônicas:
     - `modulos`: `["language", "id"]`
     - `modulos_grupos`: `["language", "id"]`
     - `modulos_operacoes`: `["language", "modulo_id", "id"]`
     - `usuarios`: `["id"]`
     - `usuarios_perfis`: `["language", "id"]`
     - `usuarios_perfis_modulos`: `["perfil", "modulo"]`
     - `usuarios_perfis_modulos_operacoes`: `["perfil", "operacao"]`
     - `categorias`: `["id"]`
3. **Pipeline do Compilador (`atualizacao-dados-recursos.php`)**:
   - Remover os 8 arquivos estáticos de qualquer lista de exclusão/reserva manual.
   - Garantir ordenação estável (por chave primária natural) e integridade dos JSONs gerados em `gestor/db/data/`.
   - Garantir que `gestor/db/data/schema-metadata.json` reflita perfeitamente as novas tabelas e regras de preservação.

### Frente B: Compilação Granular/Seletiva & Cache do Tailwind CSS
1. **Flags CLI no Gerador e no `c2f resources:sync`**:
   - Suporte a `--only=<alvo>` (ex: `--only=variaveis`, `--only=paginas`, `--only=modulos`, `--only=usuarios`).
   - Suporte a `--skip-css` (ignora a etapa 3 de compilação do Tailwind para builds ultra-rápidos de dados).
   - Suporte a `--resource=<id>` (restringe a compilação a um único componente/página/layout).
   - Repasse transparente de parâmetros CLI de `ResourcesSyncCommand.php` para o subprocesso PHP.
2. **Otimização de Cache do Tailwind CSS**:
   - Assegurar que `tailwind_recursos_compilar()` consulte o manifest `.tailwind-build-manifest.json` e pule imediatamente execuções de `tailwindcss` para recursos cujos checksums de template e classes não foram alterados.
