# req-288: 404 lento

## Relato

Ao digitar uma URL que não existe, o navegador fica carregando; a requisição do documento fica "pending" por ~5,5 s e só então vem o redirecionamento para `/404`. Acontece em produção e no Lab.

## Diagnóstico (BATCH-296)

- Medido de fora: produção 6,4 s para o `302 → /404` (páginas reais 0,2–0,7 s); Lab 1,1 s (página real 0,09 s).
- Reproduzido no PHP CLI do Lab com o front-controller e `strace`: a pausa inteira é **uma consulta** — a busca "a página existe em outro idioma?" do roteador (`gestor.php`), que rodava sem filtro de idioma e pedia `html`, `css`, `css_compiled`… Sem o índice `(language, caminho)` da req-263, o banco lia todas as páginas inteiras (1.600 no Lab; ~200 MB em produção) mesmo sem achar nada.
- Tempos da consulta: produção 7.849 ms (antiga) × 26 ms (nova); Lab ~1.000 ms × 12 ms.

## Correção

1. A busca de outro idioma pega primeiro só o `id_paginas`, com `language IN (<idiomas habilitados>)` e `LIMIT 1` (usa `idx_paginas_language_caminho`); a página inteira só é lida por id quando existe.
2. A lista de idiomas da página (roda em toda página servida) também filtra pelos idiomas habilitados, para usar o mesmo índice.

## Critérios de aceite

1. URL inexistente redireciona para `/404` sem a espera (ordem de dezenas de milissegundos no servidor).
2. Página existente só em outro idioma continua sendo servida.
3. Testes do core verdes.
