## 1. Contexto e Objetivos

Esta requisição implementa no Core do Conn2Flow a especificação [BL-032](file:///C:/Users/otavi/OneDrive/Documentos/GIT/conn2flow/memory/backlog/BL-032-usuarios-pai-filho-e-cotas-por-perfil.md), permitindo que uma Conta Titular (Usuário Pai / Organização) gerencie Sub-Usuários Vinculados (Usuários Filhos — profissionais de equipe, assistentes, recepcionistas) compartilhando o mesmo tenant de dados, sob limite configurável por plano em `usuarios_perfis`.

Além disso, como esta requisição **altera o Core do sistema**, o agente é responsável por propagar a atualização do Core para o ambiente de testes online **Dev (`snapphoton-dev`)** utilizando `./c2f manager:update-all` e `./c2f project:update-all snapphoton-dev`.

---

## 2. Escopo Arquitetural no Core (`conn2flow`)

### 2.1 Banco de Dados e Schema
1. Adicionar à tabela `usuarios` a coluna:
   - `id_usuarios_pai` (`INT NULL`, com índice e chave estrangeira para `usuarios.id_usuarios`, `ON DELETE RESTRICT`);
2. Registrar o metadado no schema do Core (`gestor/db/data/schema-metadata.json` ou migração equivalente do Core).

### 2.2 Helper Canônico no Core
1. Criar na biblioteca do Core (ex.: `gestor/bibliotecas/usuario.php` ou equivalente canônico):
   ```php
   function usuario_organizacao_id(?int $id_usuario = null): int { ... }
   ```
   - Se `$id_usuario` for nulo, resolver a partir do usuário autenticado na sessão ativa (`$_SESSION['gestor']['usuario_id']` ou JWT);
   - Se o usuário possuir `id_usuarios_pai` preenchido, retorna o ID do Pai (Organização Titular); caso contrário, retorna o próprio ID do usuário;
   - Garantir retrocompatibilidade total com módulos que utilizam `organization_id = user_id`.

### 2.3 Cotas e Limites em `usuarios_perfis`
1. Estender a configuração de perfis para suportar `max_sub_users` (int, default 0 ou ilimitado quando configurado);
2. Antes de cadastrar ou ativar um novo usuário filho, validar se a quantidade de sub-usuários ativos vinculados àquele pai não ultrapassa a cota do seu perfil;
3. Se o Usuário Pai tiver sua conta desativada/cancelada (`status != 'A'`), propagar o bloqueio de login e sessão a todos os usuários filhos vinculados.

### 2.4 Interface de Gestão de Equipe
1. Disponibilizar interface Tailwind CSS no padrão visual do Core para o titular visualizar o consumo de assentos da sua equipe (`X de Y utilizados`), listar os membros, convidar/criar novos sub-usuários e ativar/desativar acessos.

### 2.5 Testes Automatizados no Core
1. Criar testes unitários/integração cobrindo:
   - Isolamento da função `usuario_organizacao_id()`;
   - Travamento quando o limite de sub-usuários do perfil é atingido;
   - Bloqueio de sub-usuário quando a conta pai estiver inativa.

## 3. Atualização e Publicação no Ambiente Dev (`snapphoton-dev`)

> [!IMPORTANT]
> **Autorização de `update-all`:** Como esta tarefa **mexe no Core do sistema**, o uso de `./c2f manager:update-all` e `./c2f project:update-all snapphoton-dev` está explicitamente autorizado.

### Cuidados Obrigatórios com o Ambiente Dev:
1. **Versão Antiga no Dev:** O ambiente `dev.snapphoton.com` encontra-se em uma versão mais antiga do Core. Durante o processo de atualização, atente-se para possíveis divergências de schema ou arquivos legados. Não force sobrescritas destrutivas em dados próprios do projeto.
2. **Acesso Público Bloqueado no Dev:** O ambiente Dev possui bloqueio intencional de acesso público (restrito a perfis autorizados). Ao validar a atualização no Dev, lembre-se de que receber respostas restritas para navegação anônima é o comportamento correto do ambiente e **não representa defeito**.
