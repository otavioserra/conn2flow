## 1. Contexto

No BATCH-271 do lumix, harmonizar o painel do SnapPhoton com a UI 3.0 exigiu quatro contornos no projeto, todos causados por decisões fixas do núcleo:

1. `controles.css` declara "sky para ação" em ~40 hex literais. Para o painel verde, o projeto reescreveu cada seletor com prefixo `body`.
2. `c2fControles.dialogo` anexa o overlay ao `<body>`. Aberto a partir de um `<dialog>` modal (top layer), ele fica por trás e sem clique; a agenda teve de mover o overlay à mão.
3. A biblioteca de controles só entra sozinha em `layout-administrativo-tailwind*`; páginas servidas no layout do projeto (`photon-admin`) ficavam sem `controles.css/js`. O projeto incluiu por filtro.
4. A página `equipe` do núcleo tem largura (`max-w-6xl`) e respiro fixos e o layout do núcleo; o projeto copiou o HTML inteiro para trocar uma classe e o layout — bifurcação que a DECISION-056 do lumix desaconselha.

Os três backlogs de controles (BL-048, BL-049, BL-050) saíram da mesma homologação e entram juntos.

## 2. Escopo

### BATCH-308 — tema e layout por projeto

1. **Tokens de ação no `controles.css`**: `--c2fc-acao`, `--c2fc-acao-escuro`, `--c2fc-acao-texto`, `--c2fc-acao-claro`, `--c2fc-acao-suave`, `--c2fc-acao-borda`, `--c2fc-acao-foco` e `--c2fc-acao-anel` em `:root`, com os valores sky de hoje (sem mudança visual no núcleo). Todo uso de ação/seleção/foco passa a ler o token. Azul semântico de informação (`.c2fc-nota`, `.c2fc-alerta-info`) e a paleta `.c2fc-cor-*` ficam como estão.
2. **Diálogo dentro de modal**: `dialogo.alerta|confirmar|perguntar` anexam o overlay ao `<dialog>` modal aberto mais recente (top layer) quando houver; senão ao `<body>`.
3. **Controles por layout de projeto**: `$_GESTOR['project-controles-layouts']` (lista de ids de layout) faz o roteador incluir a biblioteca como já faz para `layout-administrativo-tailwind*`.
4. **Container de painel por variável**: classe `c2f-painel-pagina` no `controles.css` com `max-width: var(--c2f-painel-largura, 72rem)` e respiro `var(--c2f-painel-respiro, .5rem 0)` / `var(--c2f-painel-respiro-sm, 1.25rem 1rem)` (≥ 640 px) — os valores atuais da `equipe`. A página `equipe` adota a classe no lugar das utilities fixas.
5. **Layout por página definido pelo projeto**: `$_GESTOR['project-paginas-layout']` (`id da página => id do layout`) troca o layout de páginas do núcleo, reaproveitando o caminho do layout por perfil (sidecar do layout quando o CSS da página não cobre o layout novo).

### BATCH-309 — backlogs promovidos

1. **BL-049**: `admin-cron` e `admin-environment` deixam o `window.confirm()` e usam `c2fControles.dialogo.confirmar` (com o nativo só como reserva). `dialogo.confirmar` aceita também a forma objeto `{titulo, mensagem, ok, cancelar, perigo}`.
2. **BL-048**: select AJAX híbrido — as opções iniciais (até 50, as que vierem no HTML) continuam sendo a lista com termo vazio ou curto, a busca remota mostra os resultados com o termo e devolve as iniciais quando apagado; resposta fora de ordem é descartada; debounce de 300 ms; `data-c2f-ajax-parametros` (JSON) para parâmetros fixos.
3. **BL-050**: controle `calendario` sobre `<input type="date" data-c2f-calendario>`: mês em grade acessível (setas, Enter, Esc), navegação entre meses, `min`/`max` do input respeitados, dias **disponíveis** destacados e **indisponíveis** desabilitados a partir de `data-c2f-calendario-disponiveis` (JSON) ou de AJAX por mês (`data-c2f-calendario-opcao`, resposta `{disponiveis:[YYYY-MM-DD]}`); o input nativo segue sendo a fonte de verdade (`change` disparado nele).

## 3. Critérios de aceite

- [ ] Sem variável de projeto, o núcleo fica visualmente igual (mesmos valores computados).
- [ ] Um projeto troca a cor de ação dos controles redefinindo só os tokens.
- [ ] Confirmação aberta de dentro de `<dialog>` modal fica por cima e clicável.
- [ ] Página no layout listado em `project-controles-layouts` recebe `controles.css/js` sem chamada do módulo.
- [ ] `equipe` com largura e respiro do núcleo por padrão e ajustáveis por variável; `project-paginas-layout` serve a `equipe` em outro layout sem cópia de HTML.
- [ ] Nenhum `window.confirm()` direto fora de reserva no núcleo; select híbrido e calendário com testes Vitest.
- [ ] Vitest e PHPUnit do núcleo sem regressão; lotes registrados em `BATCH-308.md` e `BATCH-309.md`.
