# req-275: Visibilidade e link direto privado nas páginas

## 1. Pedido do Humano (15/10/2026, resumido)

Nos dois módulos que criam páginas — `admin-paginas` e `publisher-pages` (publicador de páginas):

- **"Sem permissão / acesso público" passa a vir marcado por padrão** ao adicionar (o controle continua o mesmo; só muda o padrão).
- **Nova linha "Visibilidade"**, entre "Tipo" e "Agendamento e datas", como a do `subscriptions-plans` do site (REQ-129): "Visível publicamente" (ligado por padrão) e o **link direto privado** com hash, com **Copiar** e **Gerar novo link**. Desligado, a página só abre pelo link — mesmo sendo de acesso público.
- Vai na release **3.0.4**, junto com a req-274.

## 2. Regras (decididas pelo executor, informadas ao Humano)

1. Coluna `paginas.visivel` (1 = visível; padrão 1, inclusive para as páginas existentes) e `paginas.hash_privado` (32 hex, único).
2. Página com `visivel = 0` no site: abre só com `?acesso=<hash>` correto; quem abre pelo link fica liberado na sessão para aquela página (navegação e AJAX). Sem isso: **404** (não revela que existe). Usuário logado com acesso ao `admin-paginas` ou ao `publisher-pages` continua vendo.
3. A visibilidade é independente do "sem permissão": página restrita a login continua exigindo login também pelo link.
4. Página não visível sai das listagens públicas (sitemap e índices).
5. "Gerar novo link" troca o hash no salvamento normal do formulário (com o token do formulário), como na REQ-129; o link antigo deixa de funcionar.
6. O parâmetro é `?acesso=`, não `?hash=`, para não colidir com o checkout de planos privados do site.
