## 1. Contexto & Causa-Raiz

Quando o usuário está logado com permissão de edição, a barra superior (`#c2f-site-toolbar`) é injetada automaticamente no topo das páginas públicas. Em páginas e projetos com cabeçalho fixo ou sticky no topo — como `https://ia-parceria.local/` (`<header id="c2f-header" class="fixed inset-x-0 top-0 z-50 ...">` e `<div id="c2f-progress" class="fixed left-0 top-0 z-[60] ...">`) — a barra fica **sobreposta ao layout**, cobrindo o cabeçalho e barras de progresso tanto no estado recolhido quanto com a Editbar ("Editar Página") aberta.

### Diagnóstico no Código Atual
1. **`margin-top` no `<html>` não desloca elementos `position: fixed`**:
   - Em `gestor/modulos/dashboard/dashboard.toolbar.js` (`setPageOffset(offset)`), o deslocamento aplica apenas `document.documentElement.style.setProperty('margin-top', o + 'px', 'important')`.
   - Elementos com `position: fixed; top: 0` ancoram no viewport (`y = 0`) e ignoram `margin-top` do `<html>`. O mesmo afeta elementos `sticky top-0` e wrappers `h-screen` / `min-h-screen` que podem exceder `100vh + offset`.
2. **Alturas fixas/hardcoded em vez de medição dinâmica**:
   - `gestor/modulos/dashboard/dashboard.iframe-toolbar.js` calcula `persistentHeight()` com valores fixos `MAIN_H = 30` e `EDIT_H = 44` (`30 + (editOn ? 44 : 0)`).
   - `gestor/modulos/dashboard/dashboard.toolbar.js` usa `TOOLBAR_HEIGHT = 30`.
   - Se a barra mudar de altura (quebra de linha em viewports menores, barra secundária do editor visual como `c2f-he-element-navbar`, variação de fonte/tema), o deslocamento fica dessincronizado.

---

## 2. Escopo Técnico Detalhado

### 2.1 Medição Dinâmica da Altura Real da Barra (`dashboard.iframe-toolbar.js`)
- Substituir o cálculo hardcoded (`MAIN_H + (editOn ? EDIT_H : 0)`) pela **medição real em tempo real** da altura ocupada pelas barras persistentes no topo dentro do iframe (`#c2f-toolbar-root` / barra principal + `#c2f-toolbar-editbar` quando visível, **sem** incluir dropdowns flutuantes temporários que apenas sobrepõem a página).
- Utilizar `ResizeObserver` (com fallback seguro para `window.resize` / pós-toggle) e `getBoundingClientRect().height` (arredondado com `Math.ceil` quando necessário para evitar frestas subpixel).
- Propagar o `offset` real medido na mensagem `c2f-toolbar:resize` enviada ao host (`window.parent.postMessage`), mantendo `height` (com dropdowns quando abertos) e `offset` (somente barras persistentes) claramente separados.

### 2.2 Deslocamento Dinâmico do Layout e Elementos `fixed`/`sticky` (`dashboard.toolbar.js`)
- Atualizar `setPageOffset(offset)` para:
  1. Expor o deslocamento atual em CSS Custom Property no `:root` (`--c2f-toolbar-offset: <N>px`) e sincronizar `scroll-padding-top` (preservando eventual valor pré-existente quando apropriado) para navegação por âncoras.
  2. Manter o deslocamento do fluxo normal da página (`<html>` / `<body>`, cuidando para não gerar espaço duplo nem quebra em wrappers `100vh` / `min-h-screen`).
  3. **Detectar e deslocar elementos do documento hospedeiro posicionados no topo com `position: fixed` (e `position: sticky` quando aplicável)**:
     - Somar o `offset` real ao `top` computado/original do elemento (ex.: `top: 0px` ➔ `top: <offset>px`), salvando o estado original em metadado temporário (ex.: `data-c2f-orig-top` / WeakMap) para recalcular corretamente quando o `offset` mudar (abrir/fechar "Editar Página", redimensionar tela) e restaurar fielmente caso aplicável.
     - **Exclusão estrita da própria UI do Conn2Flow**: nunca deslocar o próprio `#c2f-site-toolbar`, nem painéis/modais/overlays da Editbar ou do `html-editor.js` (ex.: `c2f-he-*`, `.c2f-toolbar-*`, containers do editor).
     - Observar inserções/alterações dinâmicas no DOM via `MutationObserver` (e recalcular em `resize` da janela e em eventos `c2f-toolbar:resize`) para cobrir headers hidratados tardiamente ou que alternam classes `fixed`/`sticky` no scroll.

### 2.3 Preservação de HTML Limpo ao Salvar (`dashboard.toolbar.js` / `html-editor.js`)
- Garantir que nenhum atributo temporário (`data-c2f-orig-top`, marcações auxiliares) nem estilo inline injetado para deslocamento da toolbar (`style="top: ..."` aplicado pela toolbar) vaze para o HTML salvo pelo `html-editor.js` (`getCleanHtml` / `reconstructOriginal` / `site-toolbar-save`).
- Preferir armazenar o valor original em memória (`WeakMap`) ou limpar explicitamente quaisquer atributos/estilos temporários antes da extração/salvamento.

### 2.4 Assets Minificados e Metadados
- Atualizar os respectivos arquivos minificados (`dashboard.toolbar.min.js` e `dashboard.iframe-toolbar.min.js`) se o repositório mantiver build/minificação sincronizada.
- Incrementar versão / `asset_version` no metadado do módulo (`gestor/modulos/dashboard/dashboard.json`) conforme regra de version bump de scripts estáticos.
