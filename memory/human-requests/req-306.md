## 1. Pilar 1 — Publicação Automática e Completa de `public_html/dist/` via Biblioteca PHP Base (Sem CLI Online nem SSH)

### 1.1 Problema Atual
1. Em `gestor/controladores/api/api.php:409-411`, o endpoint `/_api/project/update` chama `instalacao_dist_ressincronizar($project_path, $_GESTOR['dist-path'])` (`gestor/bibliotecas/instalacao-manifesto.php:579`).
2. Porém, `instalacao_dist_ressincronizar()` retorna imediatamente `verificados: 0, atualizados: 0` quando `public_html/dist/.manifest.json` ainda não existe (linha 583), e **só atualiza arquivos que já constavam no manifesto anterior** — não cria `dist/` pela primeira vez nem descobre novos assets (`.js`, `.min.js`, `.css`, imagens, fontes) entregues pelo projeto!
3. Em ambientes online de desenvolvimento/produção (HTTP/API, sem acesso SSH nem CLI online), o operador não deve depender de `c2f assets:publish --project=<id>` com `ssh_public_path` para manter `public_html/dist/` vivo e sincronizado.
4. Além disso, em `ai-workspace/en/scripts/projects/deploy-project-v2.sh:264`, o CLI executa `php cli/c2f.php assets:publish --opcional` sem `--project`, gerando ambiguidade entre publicação local e publicação no servidor de destino.

### 1.2 Solução Requerida (Contrato Único Core + CLI)
1. **Biblioteca Base PHP no Core (`gestor/bibliotecas/dist-publicacao.php` ou função canônica em `instalacao-manifesto.php` reutilizando `recursos_dist_mapear_fonte()`):**
   - Implementar uma função base pura e reutilizável em PHP puro (sem `shell_exec`, sem CLI, sem dependência de Node/SSH), ex.: `dist_publicar_completo(string $gestorRaiz, string $distPath, array $opcoes = []): array`:
     * Descobre **todos** os assets web permitidos (mesma allowlist de extensões e exclusões `NAO_PUBLICAR` hoje em `AssetsPublishCommand.php`) presentes em `$gestorRaiz/assets/` e `$gestorRaiz/modulos/` (que no servidor destino já contém o **Core instalado ali + overlay do Projeto recém-aplicado**, nunca misturando versão de Core de outra máquina!);
     * Respeita preferência por `.min.js` quando existir e não for modo `dev` (`!empty($opcoes['preferir_minificado'])` — padrão `true` em produção/servidor);
     * Cria `$distPath` e `.htaccess` automaticamente se ainda não existirem;
     * Compara `SHA-1` com o `.manifest.json` atual: reescreve atomicamente (`.tmp` + `rename`) **apenas arquivos novos ou alterados**; preserva o comportamento idempotente (0 reescritas quando nada mudou);
     * Opcionalmente suporta limpeza segura de arquivos órfãos (`limpar => true/false`, padrão conservador preservando `DEC-136` a menos que explícito);
     * Grava `.manifest.json` atomicamente e retorna resumo claro: `['criado' => bool, 'verificados' => n, 'publicados' => n, 'atualizados' => n, 'inalterados' => n, 'falhas' => n]`.
2. **Integração no Servidor (`/_api/project/update` e Atualizador do Sistema):**
   - Em `gestor/controladores/api/api.php:409-411`, substituir/evoluir a chamada para usar a nova função base completa sempre que `$_GESTOR['dist-path']` (ou caminho público resolvido pelo runtime) estiver disponível e gravável — retornando o resumo no JSON de resposta em `installation.dist`.
   - Garantir o mesmo comportamento no atualizador do sistema (`gestor/controladores/atualizacoes/atualizacoes-sistema.php`) quando o Core é atualizado pelo painel/API.
3. **Alinhamento do CLI (`AssetsPublishCommand.php` e `deploy-project-v2.sh`):**
   - Fazer `cli/src/Commands/AssetsPublishCommand.php` delegar a descoberta/publicação/manifesto para a **mesma biblioteca base PHP** (fonte única da verdade, eliminando duplicação de regra entre CLI e runtime HTTP!).
   - Revisar `ai-workspace/en/scripts/projects/deploy-project-v2.sh:254-271` para remover ambiguidade: quando o deploy for para alvo remoto (`local=false`), não confundir publicação do DocumentRoot local da máquina dev com o destino remoto (explicitar no log que o `dist/` remoto é ressincronizado pelo servidor no `/_api/project/update`).

## 2. Pilar 2 — Persistência Global da Aba Ativa no Componente UI 3.0 `data-c2f-abas`

### 2.1 Problema Atual
Em `gestor/assets/interface/controles.js` (linhas 627–661), o controle `Abas` (`[data-c2f-abas]`) sempre inicializa na primeira aba (ou na que vier com `aria-selected="true"` no HTML). Ao recarregar a página (`F5`) ou sair para uma sub-tela e retornar, o usuário perde a aba onde estava trabalhando.

### 2.2 Solução Global no UI 3.0 (`controles.js`)
1. Evoluir `Abas` em `gestor/assets/interface/controles.js`:
   - Ao clicar ou trocar de aba pelo teclado (`definir(nome)`), gravar a aba ativa em `sessionStorage` sob uma chave estável e livre de colisão entre páginas/grupos:
     * Chave padrão: `'c2f:abas:' + window.location.pathname + ':' + chaveGrupo` (onde `chaveGrupo` usa `data-c2f-abas-chave` se informado, senão `elemento.id`, senão o índice do `[data-c2f-abas]` na página).
     * Se o elemento declarar `data-c2f-abas-escopo="query"` (ou incluir um parâmetro como `data-c2f-abas-param="id"`), incorporar o valor desse parâmetro de query string na chave (ex.: ficha do paciente `?id=UUID` mantém memória isolada por paciente!).
     * Permitir desativar explicitamente quando indesejado via atributo `data-c2f-abas-sem-memoria`.
   - **Ordem de prioridade na inicialização (`montar()`):**
     1. Deep-link explícito na URL (`?tab=<nome>` ou `#<nome>` que corresponda a um `[data-c2f-aba]` existente no grupo);
     2. Última aba salva em `sessionStorage` para aquela chave (se ainda existir entre os botões do grupo);
     3. Botão com `aria-selected="true"` no HTML (ou o primeiro botão).
   - Disparar o evento/callback de mudança normalmente (ou expor a aba restaurada de forma compatível com listeners que carregam conteúdo lazy por aba).
   - Usar `try/catch` em todo acesso a `sessionStorage` (nunca quebrar em modo privado restrito ou SSR/jsdom).
2. Rodar `assets:minify` para atualizar `gestor/assets/interface/controles.min.js` e `minify-manifest.json`.
3. Auditar rapidamente se há abas nativas no Core (ex.: módulos que usam `data-c2f-abas` vs implementações manuais simples) e registrar no relatório do lote qualquer tela do Core que possa ser padronizada.
